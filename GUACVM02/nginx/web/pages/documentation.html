These are shared training credentials and must only be used inside the isolated Cyberlab environment. Do not reuse these passwords on production systems or expose the lab directly to the internet.

Automatic Guacamole login

The automatic Guacamole login is configured in: 

/opt/guacamole/nginx/nginx.conf

The following line sends the Guacamole username:

proxy_set_header X-Remote-User "guacadmin";

Guacamole reads this header through the following Docker Compose settings: 

HTTP_AUTH_ENABLED: "true"
HTTP_AUTH_HEADER: "X-Remote-User"
Automatic login is intended only for an isolated training lab. Anyone who can access the frontend can access the Guacamole connections assigned to guacadmin.

Open Guacamole directly

https://<Cyberlab-IP-or-DNS>/guacamole/

NETWORKING

NAT Configuration

The Cyberlab NAT service publishes internal lab systems to the external network using iptables.

Adding a new NAT entry

sudo nano /opt/guacamole/nat.sh

Locate the NAT_RULES array:

NAT_RULES=(
  "3001 192.168.10.2 443 FMG"
  "3002 192.168.10.3 443 FAZ"
  "3003 192.168.10.4 443 FGT"
)
Field Description Example
External port Port exposed on the Cyberlab server 3001
Destination IP Internal system IP address 192.168.10.2
Destination port Service port on the internal system 443
Name Friendly name shown in script output FMG

Example

"3007 192.168.10.20 443 WAZUH"

The service becomes available at:

https://<Cyberlab-IP-or-DNS>:3007

Apply configuration

sudo /opt/guacamole/nat.sh apply

View status

sudo /opt/guacamole/nat.sh status

Remove rules

sudo /opt/guacamole/nat.sh remove

Guacamole

Apache Guacamole provides browser-based SSH, RDP and VNC access.

Open Guacamole

https://<Cyberlab-IP-or-DNS>/guacamole/

Docker status

cd /opt/guacamole
docker compose ps

View logs

cd /opt/guacamole
docker compose logs --tail=100 guacamole

WEB PORTAL

Frontend

Cyberlab systems and connection buttons are configured in sessions.js.

Configuration file

/opt/guacamole/nginx/web/sessions.js

Add a system

{
  name: "Wazuh",
  description: "Security monitoring",
  address: "192.168.10.20",
  category: "Security",
  icon: "WAZUH",
  connections: [
    {
      type: "HTTPS",
      label: "Wazuh GUI",
      port: 3007,
      newTab: true
    }
  ]
}

When a connection uses port, the frontend uses the same IP address or DNS name that was used to open Cyberlab.

NETWORK DOCUMENTATION

Topology

The Topology page is used to document devices and connections in the Cyberlab environment.

Open the Topology page

https://<Cyberlab-IP-or-DNS>/pages/topology.html

Workflow

  1. Scan the lab network from Kali.
  2. Add discovered systems to the topology.
  3. Enter the system name, IP address and network.
  4. Connect the devices.
  5. Press Save topology.

Server storage

The topology is saved on GuacVM as:

/opt/guacamole/data/topology.json

The saved topology is loaded automatically when the page is opened from another computer.

Reset topology deletes the shared topology for all users.
