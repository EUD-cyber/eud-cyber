Login information

Cyberlab uses standard credentials for the training environment. Use the credentials below when logging in to the different systems.

System Username Password Access
All Linux servers ubuntu Password1! SSH, console or Guacamole
OPNsense GUI root opnsense HTTPS web interface
Wazuh GUI admin Password1? HTTPS web interface
Portainer admin Password1234! Docker management through the Labs page or /portainer/
Guacamole guacadmin Automatic login Nginx automatically authenticates the user through the X-Remote-User header.
Cyberlab frontend Not required Not required Direct browser access
These are shared training credentials and must only be used inside the isolated Cyberlab environment. Do not reuse these passwords on production systems or expose the lab directly to the internet.

Automatic Guacamole login

The automatic Guacamole login is configured in the Nginx configuration: 

/opt/guacamole/nginx/nginx.conf

The following line sends the Guacamole username: 

proxy_set_header X-Remote-User "guacadmin";

Guacamole is configured to read this header in docker-compose.yml: 

HTTP_AUTH_ENABLED: "true"
HTTP_AUTH_HEADER: "X-Remote-User"
This automatic login is intended only for an isolated training lab. Anyone who can access the Cyberlab frontend can access the Guacamole connections assigned to the guacadmin account.

Opening Guacamole directly

http://<Cyberlab-IP-or-DNS>/guacamole/

When Guacamole is opened through the Cyberlab Nginx server, the user should be logged in automatically without entering a username or password.

NETWORKING

NAT Configuration

The Cyberlab NAT service publishes internal lab systems to the external network using iptables.

Adding a new NAT entry

Open the following file:

/opt/guacamole/nat.sh

Locate the NAT_RULES array:

NAT_RULES=(
  "3001 192.168.10.2 443 FMG"
  "3002 192.168.10.3 443 FAZ"
  "3003 192.168.10.4 443 FGT"
)

Each entry consists of four values:

Field Description Example
External Port Port exposed on the Cyberlab server 3001
Destination IP Internal system IP address 192.168.10.2
Destination Port Service port on the internal system 443
Name Friendly name shown in script output FMG

Example

To publish a Wazuh web interface running on 192.168.10.20:443: 

"3007 192.168.10.20 443 WAZUH"

The service will then be available at:

https://<Cyberlab-IP-or-DNS>:3007

Apply the configuration

sudo /opt/guacamole/nat.sh apply

View current rules

sudo /opt/guacamole/nat.sh status

Remove Cyberlab NAT rules

sudo /opt/guacamole/nat.sh remove
After changing NAT_RULES, run the apply command again. The script removes the old Cyberlab chains and recreates them using the current configuration.

REMOTE ACCESS

Guacamole

Apache Guacamole provides browser-based SSH, RDP and VNC access.

Open Guacamole

http://<Cyberlab-IP-or-DNS>/guacamole/

Docker status

cd /opt/guacamole
docker compose ps

View logs

docker compose logs --tail=100 guacamole

WEB PORTAL

Frontend

Cyberlab systems and connection buttons are configured in sessions.js.

Configuration file

/opt/guacamole/nginx/web/sessions.js

Add a system

{
  name: "Wazuh",
  description: "Security monitoring",
  address: "192.168.10.20",
  category: "Security",
  icon: "WAZUH",
  connections: [
    {
      type: "HTTPS",
      label: "Wazuh GUI",
      port: 3007,
      newTab: true
    }
  ]
}

When a connection uses port, the frontend uses the same IP address or DNS name that the user used to open Cyberlab.
