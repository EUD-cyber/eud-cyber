Automatic Guacamole login

The automatic Guacamole login is configured in: 

/opt/guacamole/nginx/nginx.conf

The following line sends the Guacamole username:

proxy_set_header X-Remote-User "guacadmin";

Guacamole reads this header through the following Docker Compose settings: 

HTTP_AUTH_ENABLED: "true"
HTTP_AUTH_HEADER: "X-Remote-User"
Automatic login is intended only for an isolated training lab. Anyone who can access the frontend can access the Guacamole connections assigned to guacadmin.

Open Guacamole directly

https://<Cyberlab-IP-or-DNS>/guacamole/

NETWORKING

NAT Configuration

The Cyberlab NAT service publishes internal lab systems to the external network using iptables.

Adding a new NAT entry

sudo nano /opt/guacamole/nat.sh

Locate the NAT_RULES array:

NAT_RULES=(
  "3001 192.168.10.2 443 FMG"
  "3002 192.168.10.3 443 FAZ"
  "3003 192.168.10.4 443 FGT"
)
Field Description Example
External port Port exposed on the Cyberlab server 3001
Destination IP Internal system IP address 192.168.10.2
Destination port Service port on the internal system 443
Name Friendly name shown in script output FMG

Example

"3007 192.168.10.20 443 WAZUH"

The service becomes available at:

https://<Cyberlab-IP-or-DNS>:3007

Apply configuration

sudo /opt/guacamole/nat.sh apply

View status

sudo /opt/guacamole/nat.sh status

Remove rules

sudo /opt/guacamole/nat.sh remove

WEB PORTAL

Frontend

Cyberlab systems and connection buttons are configured in sessions.js.

Configuration file

/opt/guacamole/nginx/web/sessions.js

Add a system

{
  name: "Wazuh",
  description: "Security monitoring",
  address: "192.168.10.20",
  category: "Security",
  icon: "WAZUH",
  connections: [
    {
      type: "HTTPS",
      label: "Wazuh GUI",
      port: 3007,
      newTab: true
    }
  ]
}

When a connection uses port, the frontend uses the same IP address or DNS name that was used to open Cyberlab.

NETWORK DOCUMENTATION

Topology

The Topology page is used to document the Cyberlab network visually. Devices can be added to the canvas, moved freely, connected and saved centrally on the GuacVM server.

Open the Topology page

https://<Cyberlab-IP-or-DNS>/pages/topology.html

Device library

The panel on the left contains the available device types. A device can be added in two ways:

  • Click a device type to add it to the canvas.
  • Drag a device type from the library onto the canvas.
Device type Example use
FirewallOPNsense or FortiGate
RouterWAN router or lab router
SwitchPhysical or virtual network switch
LinuxKali, Ubuntu or another Linux host
WindowsWindows client or Windows Server
ServerApplication, database or security server
Docker hostServer running Docker containers
Cloud / InternetExternal network or cloud service
NetworkLAN, VLAN, DMZ or another network segment
UnknownDiscovered device that has not yet been identified

Recommended workflow

  1. Scan the lab network from Kali.
  2. Add the discovered systems to the topology.
  3. Move each device to the correct position on the canvas.
  4. Select a device and enter its properties.
  5. Use the Connect tool to create links between devices.
  6. Press Save topology.

Moving devices

Select the Select tool and drag a device to move it. The position is kept in the browser until the topology is saved.

Device properties

Select a device on the canvas to edit its information in the panel on the right.

Property Description
Device typeChanges the device category and icon.
NameThe hostname or friendly system name.
IP addressThe IPv4 or IPv6 address discovered during scanning.
NetworkThe LAN, VLAN, DMZ or network segment.
StatusActive, Unknown or Offline.
DescriptionNotes about services, roles or discovered information.

Connecting devices

Select the Connect tool. Click the first device and then click the second device. A connection is created between them.

To remove a connection:

  1. Click the connection line.
  2. Press Delete link.

Deleting devices

Select the device and press Delete device in the properties panel. Connections attached to the device are also removed.

Save topology

Press Save topology after adding, moving, editing or connecting devices.

The status box at the top of the page shows whether the topology:

  • has been loaded from the server,
  • contains unsaved changes,
  • has been saved successfully, or
  • could not contact the Topology API.

Server storage

The topology is saved centrally on GuacVM as:

/opt/guacamole/data/topology.json

Because the topology is stored on the server, the same saved topology is shown when the page is opened from another computer.

Topology API

The Topology API loads, saves and resets the shared topology.

GET    /api/topology
POST   /api/topology
DELETE /api/topology

GET    /api/topology/status

Import and export

Button Function
Export Downloads the current topology as a JSON file.
Import Loads a previously exported topology JSON file.
Importing a topology only loads it into the browser. Press Save topology afterwards to store it on the server.

Reset topology

Press Reset topology to delete the saved topology and return to an empty canvas.

Reset topology deletes the shared topology for all users. This affects every computer using the same Cyberlab installation.

Troubleshooting

Check the Topology API:

curl -k https://127.0.0.1/api/topology/status

Expected response:

{"ready":true,"saved":true}

View the saved topology:

cat /opt/guacamole/data/topology.json

Check the containers:

cd /opt/guacamole
docker compose ps
docker compose logs --tail=100 topology-api
docker compose logs --tail=100 nginx
